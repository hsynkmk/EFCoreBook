# What's New in EF Core 10

> EF Core 10 (EF10) was released **November 2025** and is a **Long-Term Support (LTS)** release,
> supported until **November 10, 2028**. It **requires the .NET 10 SDK and runtime** — it does not
> run on earlier .NET versions or on .NET Framework.

This is the curated tour of every headline EF 10 feature, with the SQL it emits and where each is
covered in depth in the course.

## 🆕 Vector data for AI

Native **`vector`** data type on **SQL Server 2025 / Azure SQL**, with `EF.Functions.VectorDistance`
(`cosine` / `euclidean` / `dot`) for semantic search, RAG, and recommendations.

```csharp
modelBuilder.Entity<Document>().Property(d => d.Embedding).HasColumnType("vector(1536)");

var matches = await ctx.Documents
    .OrderBy(d => EF.Functions.VectorDistance("cosine", d.Embedding, queryVector))
    .Take(5).ToListAsync();
```
```sql
SELECT TOP(5) ... FROM [Documents] AS [d]
ORDER BY VECTOR_DISTANCE('cosine', [d].[Embedding], @queryVector)
```
→ Full chapter: [Vector Data for AI](../01-Modeling-Data/12.Vector-Data-for-AI.md).

## 🆕 SQL Server 2025 native `json` data type

JSON columns now map to the efficient native **`json`** type (instead of `nvarchar(max)`) when you
target SQL Server 2025 or use `UseAzureSql` / compatibility level ≥ 170. Existing `nvarchar` JSON
columns auto-migrate to `json` on the next migration (opt out by pinning the column type).

```sql
CREATE TABLE [Blogs] (
    [Id] int IDENTITY PRIMARY KEY,
    [Tags] json NOT NULL,        -- native json type
    [Details] json NOT NULL
);
```
→ [JSON Columns & Primitive Collections](../01-Modeling-Data/10.JSON-Columns-and-Primitive-Collections.md).

## 🆕 LeftJoin & RightJoin LINQ operators

First-class `LeftJoin` / `RightJoin` (matching the new .NET 10 LINQ operators) replace the clunky
`GroupJoin + SelectMany + DefaultIfEmpty` pattern.

```csharp
var rows = await ctx.Posts
    .LeftJoin(ctx.Users, p => p.AuthorId, u => u.Id,
              (p, u) => new { p.Heading, Author = u != null ? u.Name : "(none)" })
    .ToListAsync();
```
→ [Advanced Querying](../02-Querying/02.Advanced-Querying.md).

## 🆕 Named query filters

Multiple global query filters per entity, each named and individually disable-able — a huge
quality-of-life win for soft-delete + multi-tenancy together.

```csharp
modelBuilder.Entity<Blog>()
    .HasQueryFilter("SoftDelete", b => !b.IsDeleted)
    .HasQueryFilter("Tenant", b => b.TenantId == tenantId);

var withDeleted = await ctx.Blogs.IgnoreQueryFilters(["SoftDelete"]).ToListAsync();  // tenant filter still applies
```
→ [Global & Named Query Filters](../01-Modeling-Data/08.Global-and-Named-Query-Filters.md).

## 🆕 ExecuteUpdate improvements

**(a) Non-expression lambdas** — conditional/dynamic updates without building expression trees:

```csharp
await ctx.Blogs.ExecuteUpdateAsync(s => {
    s.SetProperty(b => b.Views, 0);
    if (resetName) s.SetProperty(b => b.Title, "");
});
```

**(b) JSON-mapped complex properties** — update a nested JSON property with efficient `JSON_MODIFY`:

```csharp
await ctx.Blogs.ExecuteUpdateAsync(s => s.SetProperty(b => b.Details.Views, b => b.Details.Views + 1));
```
```sql
UPDATE [b] SET [Details].modify('$.Views', JSON_VALUE([b].[Details], '$.Views' RETURNING int) + 1)
FROM [Blogs] AS [b]
```
→ [Bulk Operations](../03-Saving-and-Concurrency/05.Bulk-Operations.md).

## 🆕 Complex types: optional + JSON + collections

- **Optional** complex types (`Address? BillingAddress`) — needs at least one required member.
- Complex types mapped to **JSON** via `.ToJson()`.
- **Complex type collections** supported.

→ [Owned Entities & Complex Types](../01-Modeling-Data/04.Owned-Entities-and-Complex-Types.md).

## 🆕 Parameterized collection padding (better plan caching)

The default translation for parameterized collections now expands each value into its own scalar
parameter **and pads** the list (to a Fibonacci-ish count) so fewer distinct SQL strings are
generated — better plan-cache hit rate *and* cardinality hints for the optimizer.

```sql
-- ids list of 8 values → padded to 10 parameters
WHERE [b].[Id] IN (@ids1, @ids2, ..., @ids10)
```

## 🆕 Custom default-constraint names

```csharp
modelBuilder.Entity<Post>().Property(p => p.CreatedDate).HasDefaultValueSql("GETDATE()", "DF_Post_CreatedDate");
// or name them all automatically:
modelBuilder.UseNamedDefaultConstraints();
```

## 🆕 Azure Cosmos DB improvements

- **Full-text search**: `EnableFullTextSearch()` / `IsFullTextIndex()` + `EF.Functions.FullTextContains`.
- **Vector** model API renamed to `IsVectorProperty` / `IsVectorIndex`.
- Required properties get a **default value** when missing from old documents (easier schema
  evolution) instead of throwing.
- `ExecutionStrategy` used for query execution (retries).

## 🆕 Other notable changes

- **Migrations apply per-step again** — EF 10 **reverted** EF 9's single-transaction wrapping
  because it caused problems in several deployment scenarios.
- **Simplified parameter names** in generated SQL (`@city` instead of `@__city_0`) — far more
  readable logs.
- `MIN`/`MAX` over `DISTINCT` optimized.
- SQLite: `AUTOINCREMENT` can be disabled; value-converter PKs supported.

## ⚖️ Should you adopt EF 10?

| You are… | Recommendation |
|----------|----------------|
| On .NET 10 already / starting fresh | **Yes** — LTS to 2028, all the new features |
| On EF 8 LTS, conservative | Plan the move; EF 8 supported until Nov 2026 |
| Need vector / SQL 2025 JSON | EF 10 is the path |
| Can't move to .NET 10 yet | Stay on EF 8/9 (EF 10 requires .NET 10) |

## ✅ Key Takeaways

- EF 10 is **LTS (→ Nov 2028)**, **requires .NET 10**.
- Headliners: **vector data**, **SQL 2025 `json` type**, **LeftJoin/RightJoin**, **named query
  filters**, **ExecuteUpdate** (non-expression lambdas + JSON), **complex type** JSON/optional/
  collections, **parameterized collection padding**.
- Migrations are **per-step** again; logged SQL has **readable parameter names**.
