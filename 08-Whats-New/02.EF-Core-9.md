# What's New in EF Core 9

> EF Core 9 (EF9) was released **November 2024** as a **Short-Term Support (STS)** release,
> supported until **November 10, 2026**. It targets **.NET 8**, so it runs on .NET 8 (LTS) or
> .NET 9.

EF 9 was a big release for **Cosmos DB**, **query translation**, and **startup performance**.

## 🆕 Azure Cosmos DB — major rewrite

Large parts of the Cosmos provider were rewritten:
- **Partition-key extraction** from LINQ — queries route to the right partition automatically,
  cutting RU cost.
- **Hugely expanded LINQ translation** — primitive collections, aggregates, more functions,
  `DateTime` members, `StringComparison.OrdinalIgnoreCase`.
- **Simplified `id`** (no discriminator prefix) and **`$type`** discriminator (JSON-polymorphism
  standard) — better interop, but a breaking change for existing documents.
- **`ToPageAsync`** with continuation tokens for efficient pagination.
- **`FromSql`** (parameterized) replacing injection-prone `FromSqlRaw`.
- **RBAC** for data-plane operations; synchronous I/O blocked by default.

> ⚠️ Several Cosmos changes are **breaking** — read the EF 9 breaking-changes guide before
> upgrading an existing Cosmos app.

## 🆕 MSBuild-integrated compiled model (faster startup)

Compile the model at **build time** so large models don't pay a startup cost:

```xml
<PropertyGroup>
  <EFOptimizeContext>true</EFOptimizeContext>
  <EFScaffoldModelStage>build</EFScaffoldModelStage>
</PropertyGroup>
```

The compiled model regenerates automatically whenever the model changes.
→ [Compiled & Precompiled Queries](../02-Querying/06.Compiled-and-Precompiled-Queries.md).

## 🆕 Read-only primitive collections

EF 8 introduced primitive collections (arrays/mutable lists). EF 9 extended them to
**`IReadOnlyList<T>`**, **`IReadOnlyCollection<T>`**, and **`ReadOnlyCollection<T>`** — great for
DDD-style immutable entities.

```csharp
public class DogWalk {
    public int Id { get; set; }
    public ReadOnlyCollection<DateOnly> DaysVisited { get; set; } = null!;   // mapped by convention
}
```
→ [JSON Columns & Primitive Collections](../01-Modeling-Data/10.JSON-Columns-and-Primitive-Collections.md).

## 🆕 Control over parameterized collections

EF parameterizes inline collections so SQL stays stable across calls (good for plan caching), but
sometimes the optimizer wants constants. EF 9 added control:

```csharp
// Force constants for this query (better cardinality info, more plan variants)
await ctx.Posts.Where(e => EF.Constant(ids).Contains(e.Id)).ToListAsync();

// Or set the default behavior on the context:
opt.UseSqlServer(cs, o => o.TranslateParameterizedCollectionsToConstants());   // and EF.Parameter to override per-query
```
(EF 10 then introduced **padding** as a smarter default — see [EF 10](01.EF-Core-10.md).)

## 🆕 `UseAzureSql` / `UseAzureSynapse`

Tell EF precisely which SQL flavor you target so it can use database-specific features and work
around limitations:

```csharp
opt.UseAzureSql(connectionString);     // Azure SQL — e.g. uses the dedicated JSON type
opt.UseAzureSynapse(connectionString); // works around Synapse LIKE/ESCAPE limitations
```

## 🆕 Inlined uncorrelated subqueries (fewer round-trips)

An `IQueryable` referenced inside another query that previously ran as a **separate** round-trip
can now be **inlined** into a single SQL statement:

```csharp
var dotnetPosts = ctx.Posts.Where(p => p.Title.Contains(".NET"));
var results = await dotnetPosts
    .Where(p => p.Id > 2)
    .Select(p => new { Post = p, TotalCount = dotnetPosts.Count() })   // one query in EF 9, not two
    .Skip(2).Take(10).ToArrayAsync();
```

## 🆕 LINQ & SQL translation polish

- `ToHashSetAsync`.
- `TimeOnly.FromDateTime` / `FromTimeSpan` translated on SQL Server.
- `ToString()` over enums translated.
- `string.Join` → `CONCAT_WS`.
- `EF.Functions.PatIndex` → `PATINDEX`.
- Simplified `CASE`/boolean SQL (e.g. bitwise NOT `~` instead of nested `CASE`).
- `Complex types`: `GroupBy` and per-member `ExecuteUpdate` support.

## ⚖️ EF 9 in context

| | EF 8 | **EF 9** | EF 10 |
|--|------|----------|-------|
| Support | LTS → Nov 2026 | **STS → Nov 2026** | LTS → Nov 2028 |
| .NET target | .NET 8 | .NET 8 (runs on 8/9) | .NET 10 |
| Theme | Modeling (complex types, JSON, primitives, HierarchyId) | **Cosmos rewrite, startup perf, query polish** | Vector/AI, SQL 2025 JSON, joins, named filters |

> EF 9 is **STS** (18 months). For a long-lived app, EF 8 (LTS) or EF 10 (LTS) are the
> longer-supported choices; EF 9 is great if you want its features and will keep upgrading.

## ✅ Key Takeaways

- EF 9 is **STS (→ Nov 2026)**, targets **.NET 8**.
- Biggest wins: **Cosmos rewrite**, **MSBuild compiled model** (startup), **read-only primitive
  collections**, **inlined subqueries**, **`UseAzureSql`**, lots of **LINQ translation** polish.
- Several **Cosmos breaking changes** — check before upgrading existing Cosmos apps.
- For long-term support, prefer EF 8 or EF 10 (both LTS).
