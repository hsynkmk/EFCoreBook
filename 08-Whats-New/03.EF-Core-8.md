# What's New in EF Core 8

> EF Core 8 (EF8) was released **November 2023** as a **Long-Term Support (LTS)** release,
> supported until **November 10, 2026**. It targets **.NET 8**. EF 8 is the version many
> conservative shops still run in production — and it's where a lot of "modern EF" began.

EF 8 was a landmark modeling release: **complex types**, **primitive collections**, **JSON
columns**, **HierarchyId**, and native **`DateOnly`/`TimeOnly`** all arrived here.

## 🆕 Complex types (value objects)

Before EF 8, value objects (Address, Money) had to be modeled as **owned entities** — which are
secretly entities with a hidden key. **Complex types** model them properly: no key, no identity,
no tracking, instances shareable.

```csharp
public class Address { public required string Line1 { get; set; } public required string City { get; set; } public required string Country { get; set; } }

modelBuilder.Entity<Customer>(b => b.ComplexProperty(c => c.Address));
```

Columns are added to the owner's table (`Address_Line1`, `Address_City`, …). (EF 9 added
`GroupBy`/`ExecuteUpdate`; EF 10 added optional, JSON, and collections.)
→ [Owned Entities & Complex Types](../01-Modeling-Data/04.Owned-Entities-and-Complex-Types.md).

## 🆕 Primitive collections

Map arrays / lists of primitives to a single JSON column — and query them with LINQ:

```csharp
public class Pub {
    public int Id { get; set; }
    public List<string> Beers { get; set; } = new();
    public IList<DateOnly> DaysVisited { get; set; } = new List<DateOnly>();
}

var thisYear = DateTime.Now.Year;
var visited = await ctx.Pubs.Where(p => p.DaysVisited.Any(v => v.Year == thisYear)).ToListAsync();
```
```sql
WHERE EXISTS (SELECT 1 FROM OpenJson([p].[DaysVisited]) AS [d]
              WHERE DATEPART(year, CAST([d].[value] AS date)) = @thisYear)
```

Crucially, EF *knows the element type*, so it emits type-correct SQL (`DATEPART`, typed parameters).
→ [JSON Columns & Primitive Collections](../01-Modeling-Data/10.JSON-Columns-and-Primitive-Collections.md).

## 🆕 JSON columns

Map owned entities / nested aggregates to a JSON column with `.ToJson()`:

```csharp
modelBuilder.Entity<Order>().OwnsOne(o => o.Shipping, b => b.ToJson());
modelBuilder.Entity<Order>().OwnsMany(o => o.Lines, b => b.ToJson());

var big = await ctx.Orders.Where(o => o.Lines.Any(l => l.Quantity > 10)).ToListAsync();
```

EF queries into the JSON with `OPENJSON` (SQL Server) / `jsonb` (Postgres). (EF 10 adds the native
SQL 2025 `json` type and `JSON_MODIFY`-based `ExecuteUpdate`.)

## 🆕 HierarchyId (SQL Server)

Official, idiomatic `HierarchyId` for tree data (org charts, file systems, taxonomies):

```csharp
// dotnet add package Microsoft.EntityFrameworkCore.SqlServer.HierarchyId
opt.UseSqlServer(cs, x => x.UseHierarchyId());

public class Halfling { public int Id { get; set; } public HierarchyId Path { get; set; } = null!; }

var descendants = await ctx.Halflings.Where(h => h.Path.IsDescendantOf(ancestor.Path)).ToListAsync();
```
→ [HierarchyId & Tree Data](../01-Modeling-Data/11.HierarchyId-and-Tree-Data.md).

## 🆕 DateOnly / TimeOnly on SQL Server

`DateOnly` and `TimeOnly` (from .NET 6) finally map natively on SQL Server (`date` / `time`) —
they were already supported on SQLite/PostgreSQL/MySQL.

```csharp
public class Term { public DateOnly FirstDay { get; set; } public DateOnly LastDay { get; set; } }
public class OpeningHours { public TimeOnly OpensAt { get; set; } public TimeOnly ClosesAt { get; set; } }
```

No more abusing `DateTime` for a pure date or `TimeSpan` for a time of day. Note: scaffolding now
generates `DateOnly`/`TimeOnly` for `date`/`time` columns (a breaking change for database-first).
→ [Value Conversions](../01-Modeling-Data/05.Value-Conversions.md).

## 🆕 `SqlQuery<T>` for primitive / unmapped results

Run raw SQL that returns scalars or ad-hoc DTOs **without** registering a keyless entity:

```csharp
var ids = await ctx.Database.SqlQuery<int>($"SELECT Id FROM Blogs WHERE Views > {threshold}").ToListAsync();
```
→ [Raw SQL Queries](../02-Querying/05.Raw-SQL-Queries.md).

## 🆕 Other EF 8 improvements

- **Sentinel values** — better control over when a property is considered "set" for default-value
  generation.
- **TPH discriminator columns** get a sensible max length (smallest Fibonacci covering all values)
  instead of `nvarchar(max)`.
- **Lazy-loading** improvements for no-tracking queries.
- **Math translations**, more **LINQ** translations, and `ExecutePragma`/SQLite improvements.
- `has-pending-model-changes` CLI command for CI.

## ⚖️ Why EF 8 still matters

- It's **LTS until Nov 2026** — plenty of production apps run it deliberately.
- It established the **modern modeling toolkit** (complex types, JSON, primitive collections,
  HierarchyId, DateOnly/TimeOnly) that EF 9/10 build on.
- If you can't move to .NET 10 (required by EF 10), **EF 8 is the safe LTS** to be on.

## ✅ Key Takeaways

- EF 8 is **LTS (→ Nov 2026)**, targets **.NET 8**.
- It introduced the modern modeling features: **complex types, primitive collections, JSON
  columns, HierarchyId, native DateOnly/TimeOnly, `SqlQuery<T>`**.
- Most of EF 9/10's modeling work **extends** these EF 8 foundations.
- If you're stuck below .NET 10, EF 8 is the LTS to target.
