# Study Plan: From Beginner to Senior EF Core

## 🧠 How to Use This

A concrete roadmap through the whole course at ~1 hour/day. The **order** matters more than the
pace. The single most effective habit: for every topic, **read the painful "before" code, then do
the 🎯 Practice before peeking at the solution.** EF sticks when you fix bad code with it.

> 💡 The senior EF mindset: **always know the SQL.** Read the "⚡ Generated SQL" section in every
> file. If you can predict EF's SQL from the LINQ, you've arrived.

## 📅 The 6-Week Plan

### Week 1 — Foundations
[Module 00](../00-Foundations/README.md): what EF is, setup (EF 10 / .NET 10), first CRUD,
providers.
**Goal:** stand up an EF 10 project, do CRUD, and read the SQL each operation emits.

### Week 2 — Modeling (part 1)
[Module 01](../01-Modeling-Data/README.md), files 01–06: DbContext, configuration
(`IEntityTypeConfiguration`), relationships, owned vs **complex types**, value conversions, shadow
properties.
**Goal:** model a small domain cleanly with Fluent API in per-entity config classes.

### Week 3 — Modeling (part 2, the modern features)
[Module 01](../01-Modeling-Data/README.md), files 07–12: indexes, **global & named query filters**,
temporal tables, **JSON columns & primitive collections**, **HierarchyId**, **vector data**.
**Goal:** use the EF 8/9/10 modeling features; implement soft-delete + multi-tenancy with named
filters.

### Week 4 — Querying & Saving
[Module 02](../02-Querying/README.md) (LINQ, loading strategies, split queries, raw SQL,
no-tracking) + [Module 03](../03-Saving-and-Concurrency/README.md) (change tracking, transactions,
concurrency, **ExecuteUpdate/Delete**, interceptors).
**Goal:** write efficient queries (predict the SQL), handle concurrency, and use bulk operations +
interceptors.

### Week 5 — Migrations & Performance
[Module 04](../04-Migrations-and-Schema/README.md) (basics → production → expand-contract) +
[Module 05](../05-Performance/README.md) (fundamentals, **DbContext pooling**, compiled queries,
bulk perf, **diagnosing slow queries**).
**Goal:** run safe production migrations and diagnose a slow query end-to-end with evidence.

### Week 6 — Production, Testing & Modern Features
[Module 06](../06-Production/README.md) (DI, config, logging, resilience, security) +
[Module 07](../07-Testing/README.md) (SQLite in-memory, Testcontainers) +
[Module 08](../08-Whats-New/README.md) (EF 10/9/8 deep dives) +
[Module 09](../09-Beyond/README.md) (anti-patterns, EF vs Dapper).
**Goal:** ship EF with confidence — DI lifetimes right, secrets safe, retries on, tested against a
real engine, and the judgment to know when *not* to use EF.

## 🛠️ The Most Important Habit: Read the SQL

For every query you write:
1. Predict the SQL from the LINQ.
2. Confirm with **`ToQueryString()`** or **`LogTo`** + **`TagWith`**.
3. If it surprises you, find out why (translation limit? N+1? cartesian?).

Do this for ~30 queries and "thinking in both LINQ and SQL" becomes automatic — the core senior
skill.

## ✅ Readiness Signals

You're senior-EF-ready when you can:
- **Predict the SQL** EF generates from a LINQ query, and capture it to confirm.
- Choose **loading strategy**, **tracking**, and **bulk vs tracked** writes deliberately.
- Diagnose a slow query: tag → log → `ToQueryString` → execution plan → index/projection fix.
- Run **safe production migrations** (idempotent/bundles, expand-contract).
- Get **DI lifetimes** right (no captive dependency) and **secrets** out of source.
- Test against a **real engine** (SQLite in-memory + Testcontainers), never mock `DbSet`.
- Know the **EF 8/9/10** feature set and when to reach for **Dapper/raw** instead.

## 🔜 What's Next (toward senior)

EF Core is one slice of back-end mastery. Natural next steps: **databases deeper** (SQL tuning,
indexing internals, query plans), **architecture** (Clean/Hexagonal, DDD, CQRS at scale),
**distributed systems** (outbox, sagas, eventual consistency), and **observability/operations**.
EF fits inside all of these — you now have the data-access layer handled.
