# Configuration & Connection Strings

## 🧠 Intuition

A connection string is a **secret** (it often contains credentials) and an **environment-specific
value** (dev, staging, prod point at different databases). Both facts mean it must **not** live
hard-coded in source. .NET's configuration system layers multiple sources — appsettings, user
secrets, environment variables, Key Vault — so the right value flows in per environment without
ever committing a password.

> 💡 **Rule:** the connection string in `appsettings.json` should be a non-secret default (e.g.
> LocalDB) or a placeholder. Real credentials come from **user secrets** (dev) and **a secret
> store** (prod).

## 📐 The configuration layering

Later sources override earlier ones:

```
appsettings.json
  → appsettings.{Environment}.json   (appsettings.Production.json)
    → User Secrets                   (dev machine only)
      → Environment variables        (containers, CI)
        → Azure Key Vault / AWS Secrets Manager  (prod)
```

`builder.Configuration` reads all of these; `GetConnectionString("Default")` returns the
highest-priority value present.

## 💻 The standard wiring

```csharp
builder.Services.AddDbContext<BloggingContext>(opt =>
    opt.UseSqlServer(builder.Configuration.GetConnectionString("Default")));
```

`appsettings.json` (committed — non-secret default only):
```json
{
  "ConnectionStrings": {
    "Default": "Server=(localdb)\\mssqllocaldb;Database=Blogging;Trusted_Connection=True;TrustServerCertificate=True"
  }
}
```

## 💻 Dev: user secrets (never committed)

```bash
dotnet user-secrets init
dotnet user-secrets set "ConnectionStrings:Default" "Server=devsql;Database=Blogging;User Id=app;Password=...;TrustServerCertificate=True"
```

User secrets live outside the repo (in your user profile) and override `appsettings.json`
automatically in Development. Your real dev credentials never touch git.

## 💻 Prod: environment variables / Key Vault

**Environment variable** (containers, app services) — note the `__` separator maps to the config
hierarchy:
```bash
ConnectionStrings__Default="Server=prodsql;Database=Blogging;..."
```

**Azure Key Vault:**
```csharp
builder.Configuration.AddAzureKeyVault(
    new Uri("https://my-vault.vault.azure.net/"),
    new DefaultAzureCredential());
// then ConnectionStrings:Default (or a secret named ConnectionStrings--Default) resolves from the vault
```

**Even better — passwordless auth.** On Azure, use **Managed Identity** so there's no password in
the connection string at all:
```
Server=tcp:prodsql.database.windows.net;Database=Blogging;Authentication=Active Directory Default;
```
`DefaultAzureCredential` + AAD auth means nothing secret is stored anywhere.

## 💻 Useful connection-string options (SQL Server)

```text
Server=...;Database=...;
Trusted_Connection=True;            -- Windows auth (dev)
TrustServerCertificate=True;        -- dev/local; in prod use a real cert + Encrypt=True
Encrypt=True;                       -- encrypt the connection (prod)
Max Pool Size=100; Min Pool Size=5; -- ADO.NET connection pool tuning
Connect Timeout=30;
Application Name=MyApp;             -- shows up in SQL Server logs/DMVs — set it!
```

> 💡 Set **`Application Name`** — it makes your app's connections identifiable in
> `sys.dm_exec_sessions` and profiler traces. Cheap, hugely helpful during incidents.

## ⚖️ Where the connection string should live

| Environment | Source | Secret? |
|-------------|--------|---------|
| Local dev | **User secrets** | Yes — never committed |
| CI | **Environment variables / pipeline secrets** | Yes |
| Staging / Prod | **Key Vault / Secrets Manager**, or **Managed Identity** | Yes (or none, with MI) |
| `appsettings.json` (committed) | Non-secret default (LocalDB) or placeholder | No |

## 🚫 Common mistakes

```csharp
// ❌ Hard-coded connection string in OnConfiguring or appsettings with a real password
optionsBuilder.UseSqlServer("Server=prod;Password=hunter2;...");

// ❌ Committing appsettings.Production.json with prod credentials
// ✅ keep prod secrets out of the repo entirely (Key Vault / env vars / MI)

// ❌ TrustServerCertificate=True in production
// ✅ Encrypt=True with a valid certificate
```

## 🆕 Latest EF Notes (8 / 9 / 10)

- Configuration is a .NET host concern, not EF-specific — stable across EF 8/9/10.
- **EF 9** `UseAzureSql` pairs naturally with Azure config + Managed Identity for Azure SQL.

## 🌍 Real-world production tips

- **Passwordless (Managed Identity)** wherever the platform supports it — no secret to leak.
- Always set **`Application Name`** in the connection string.
- Use **`Encrypt=True`** + a real certificate in production; `TrustServerCertificate=True` is for
  local only.
- Keep `appsettings.{Environment}.json` for **non-secret** environment differences (timeouts,
  feature flags) — secrets go to the vault.
- Validate config at startup (fail fast if the connection string is missing).

## 🎯 Practice (with full solutions)

### 1. Get secrets out of source — `Easy`
**Smelly code:** `appsettings.json` checked into git with a prod password.
**Solution:**
```bash
# dev
dotnet user-secrets set "ConnectionStrings:Default" "Server=devsql;...;Password=..."
# prod: set an env var in the host, or use Key Vault
ConnectionStrings__Default="Server=prodsql;...;Encrypt=True"
```
And reduce `appsettings.json` to a LocalDB default. Rotate the leaked password.
**Why it's better:** no credential in the repo; each environment supplies its own; the committed
default is harmless.

### 2. Go passwordless on Azure — `Medium`
**Task:** Connect to Azure SQL with no password stored anywhere.
**Solution:**
```csharp
builder.Services.AddDbContext<BloggingContext>(opt =>
    opt.UseAzureSql("Server=tcp:prod.database.windows.net;Database=Blogging;Authentication=Active Directory Default;Encrypt=True;"));
```
Grant the app's **Managed Identity** access to the database; `DefaultAzureCredential` handles the
token.
**Why it's better:** there is literally no secret to leak, rotate, or commit.

## ✅ Key Takeaways

- Connection strings are **secrets + environment-specific** — keep them out of source.
- Layer config: **appsettings (non-secret default) → user secrets (dev) → env vars / Key Vault
  (prod)**.
- Prefer **Managed Identity / passwordless** auth where possible.
- Use **`Encrypt=True`** in prod, set **`Application Name`**, validate config at startup.
