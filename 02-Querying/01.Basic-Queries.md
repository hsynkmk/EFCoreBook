# Basic Queries: LINQ to Entities

## 🧠 Intuition

EF's job is to translate **LINQ over `DbSet<T>`** into **SQL** that the database runs. You think
in C# objects and predicates; EF figures out the SQL. The trick is to know what *will* and *won't*
translate — and to never accidentally pull a whole table into memory.

> 💡 The single rule: **filter, sort, project, paginate — all *before* `ToListAsync()`**. Once
> data hits memory, you've left EF's translator and the database can't help you.

## 🎯 The Problem

```csharp
// ❌ Before: filtering in memory after materialization
var blogs = await ctx.Blogs.ToListAsync();                     // pulls EVERY column for EVERY blog
var recent = blogs.Where(b => b.Views > 1000).ToList();        // then we filter in memory
```

The database returned every row, every column, untracked. We could have asked for ten and gotten
ten.

## 💻 The right shape

```csharp
var recentTitles = await ctx.Blogs
    .Where(b => b.Views > 1000)                                // WHERE
    .OrderByDescending(b => b.Views)                            // ORDER BY
    .Select(b => new { b.Id, b.Title })                         // SELECT only what we need
    .Take(20)                                                    // TOP 20 / LIMIT 20
    .AsNoTracking()                                              // read-only path — skip change tracker
    .ToListAsync();                                              // execute (one round-trip)
```

**⚡ Generated SQL:**
```sql
SELECT TOP(20) [b].[Id], [b].[Title]
FROM [Blogs] AS [b]
WHERE [b].[Views] > 1000
ORDER BY [b].[Views] DESC
```

## 📐 LINQ operators that translate

| LINQ | SQL |
|------|-----|
| `Where`, `Any`, `All` | `WHERE`, `EXISTS`, `NOT EXISTS` |
| `OrderBy`/`Descending`, `ThenBy` | `ORDER BY` |
| `Skip`, `Take` | `OFFSET`/`FETCH NEXT` or `LIMIT/OFFSET` |
| `Select` | column projection |
| `Distinct` | `SELECT DISTINCT` |
| `GroupBy` | `GROUP BY` (with limitations — see [Advanced Querying](02.Advanced-Querying.md)) |
| `Join`, `GroupJoin` | `INNER JOIN`, `LEFT JOIN` (EF 10 adds clean **`LeftJoin`/`RightJoin`**) |
| `Count`, `Sum`, `Avg`, `Min`, `Max` | aggregate functions |
| `Contains` on a collection | `IN (...)` |
| `string.StartsWith/EndsWith/Contains` | `LIKE 'x%'` / `LIKE '%x'` / `LIKE '%x%'` |

What **doesn't** translate (per provider):
- Most arbitrary C# methods (`MyHelper.ProcessAsync(x)`).
- Some `DateTime`/`string` operations not in the provider's translation set.
- Things only the **client** can compute — EF will throw with a helpful message ("could not be
  translated").

## 💻 Patterns to memorize

### Single entity by primary key
```csharp
var blog = await ctx.Blogs.FindAsync(42);                       // uses identity map; may hit DB
// or
var blog = await ctx.Blogs.SingleAsync(b => b.Id == 42);
```

### Projection to a DTO
```csharp
var summaries = await ctx.Blogs
    .Where(b => b.Views > 1000)
    .Select(b => new BlogSummaryDto(b.Id, b.Title, b.Views))
    .ToListAsync();
public record BlogSummaryDto(int Id, string Title, int Views);
```

Projecting to a slim DTO is the biggest single perf lever — fewer columns over the wire, no
change-tracking overhead.

### Pagination
```csharp
var page = await ctx.Blogs
    .OrderBy(b => b.Id)                                          // stable ordering required for paging
    .Skip((pageNumber - 1) * pageSize)
    .Take(pageSize)
    .ToListAsync();
```

> ⚠️ For deep pages, prefer **keyset pagination** (`Where(b => b.Id > lastSeenId)`) over `Skip`.
> SQL `OFFSET` reads and discards every skipped row.

### Async + cancellation
```csharp
await ctx.Blogs.ToListAsync(cancellationToken);
```
Always pass `CancellationToken` in server code. Sync calls block a thread.

## ⚖️ Common mistakes (the perf footguns)

```csharp
// ❌ Materializing, then filtering
var blogs = await ctx.Blogs.ToListAsync();
var some = blogs.Where(b => b.Views > 1000);

// ❌ Awaiting a query just to count it
var count = (await ctx.Blogs.ToListAsync()).Count;
// ✅ ask the DB
var count = await ctx.Blogs.CountAsync();

// ❌ Forgetting AsNoTracking on read-only paths
// ✅ var blogs = await ctx.Blogs.AsNoTracking().ToListAsync();

// ❌ Skip without a stable order = inconsistent pages
// ✅ OrderBy something unique (usually Id) before Skip/Take
```

## 🆕 Latest EF Notes (8 / 9 / 10)

- **EF 8:** `Database.SqlQuery<T>("...")` for raw-SQL primitive results — see
  [Raw SQL Queries](05.Raw-SQL-Queries.md).
- **EF 9:** read-only primitive collections; many LINQ translation improvements; `ToHashSetAsync`.
- **EF 10:** **`LeftJoin`** / **`RightJoin`** LINQ operators (matching .NET 10); cleaner parameter
  names in the SQL (`@city` instead of `@__city_0`); parameterized collection padding.

## 🌍 Real-world production tips

- **Always project to DTOs in read-only paths.** Entities carry a tracking snapshot you don't
  need.
- **`AsNoTracking()`** for any query whose results aren't mutated and saved.
- **Keyset pagination** for endless lists / infinite scroll.
- **Capture the generated SQL** with `LogTo` or query tags during development so you can spot
  surprises.

## 🎯 Practice (with full solutions)

### 1. Fix a slow listing — `Easy`
**Smelly code:**
```csharp
var blogs = await ctx.Blogs.ToListAsync();
var top = blogs.OrderByDescending(b => b.Views).Take(10).Select(b => new { b.Id, b.Title });
```
**Solution:**
```csharp
var top = await ctx.Blogs
    .OrderByDescending(b => b.Views)
    .Take(10)
    .Select(b => new { b.Id, b.Title })
    .AsNoTracking()
    .ToListAsync();
```
**Why it's better:** the database does the work; we read 10 rows and 2 columns instead of N rows
× all columns.

### 2. Keyset pagination — `Medium`
**Task:** `GET /blogs?after={id}&take=20` should return the next 20 blogs after a given id.
**Solution:**
```csharp
public async Task<List<Blog>> NextPageAsync(int afterId, int take, BloggingContext ctx) =>
    await ctx.Blogs
        .Where(b => b.Id > afterId)
        .OrderBy(b => b.Id)
        .Take(take)
        .AsNoTracking()
        .ToListAsync();
```
**Why it's better:** `WHERE [Id] > @after ORDER BY [Id]` uses the PK index directly — constant
time per page even on page 1,000,000. `Skip(1_000_000)` would read and discard a million rows
first.

## ✅ Key Takeaways

- LINQ over `DbSet<T>` translates to SQL — **filter, sort, project, paginate before `ToListAsync`**.
- **Project to slim DTOs**; **`AsNoTracking`** on read-only paths; **keyset pagination** for big
  lists.
- Always pass `CancellationToken`.
- EF 10's `LeftJoin`/`RightJoin` are major LINQ ergonomics wins (see [Advanced Querying](02.Advanced-Querying.md)).
