# Vector Data for AI

> 🆕 **EF Core 10 headline feature.** Native `vector` data type on SQL Server 2025 / Azure SQL,
> plus `VECTOR_DISTANCE()` for similarity search. Cosmos DB also has first-class vector support
> as of EF 9/10. PostgreSQL users typically reach for the `pgvector` community extension.

## 🧠 Intuition

AI models turn text, images, or audio into **vectors** (arrays of floats called **embeddings**)
that capture meaning. Two similar inputs land near each other in this vector space. To build
**semantic search**, **retrieval-augmented generation (RAG)**, or recommendation, you store an
embedding for each document and, at query time, find the **nearest** embeddings to your query's
embedding.

> 💡 **Analogy — coordinates on a map.** Plain text search is like asking "is this string in the
> file?". Vector search is like asking "what's the *closest landmark* to where I am?" — the
> database measures distance in many dimensions and returns the nearest hits.

EF 10 makes this first-class: `Vector` as a property type, native column type on the database side,
LINQ functions to compute distance and rank, and an index for fast approximate search.

## 🎯 The Problem

```csharp
// ❌ Before EF 10: store embeddings as nvarchar(max) / blob and query in app code
public class Document { public int Id { get; set; } public string Embedding { get; set; } = ""; }   // serialized array
// Every "find similar" request reads ALL embeddings into memory, computes distances in C# → O(N) scan,
// and the DB optimizer is useless.
```

That's the brute-force pattern. With EF 10's vector support, the database does the math, uses an
index, and returns the top-K in milliseconds.

## 💻 The model (EF 10, SQL Server 2025 / Azure SQL)

```csharp
using Microsoft.Data.SqlTypes;
using Microsoft.EntityFrameworkCore;

public class Document {
    public int Id { get; set; }
    public string Content { get; set; } = "";
    public SqlVector<float> Embedding { get; set; } = default;   // EF 10 vector
}

modelBuilder.Entity<Document>()
    .Property(d => d.Embedding)
    .HasColumnType("vector(1536)");                              // dimensions of the embedding model
```

**⚡ Generated SQL:**
```sql
CREATE TABLE [Documents] (
    [Id] int IDENTITY PRIMARY KEY,
    [Content] nvarchar(max) NOT NULL,
    [Embedding] vector(1536) NOT NULL
);
```

## 💻 Inserting an embedding

```csharp
float[] embedding = await myEmbeddingModel.EmbedAsync(content);   // 1536 floats from e.g. OpenAI
ctx.Documents.Add(new Document {
    Content = content,
    Embedding = new SqlVector<float>(embedding)
});
await ctx.SaveChangesAsync();
```

## 💻 Similarity search (nearest neighbors)

```csharp
float[] query = await myEmbeddingModel.EmbedAsync("What is RAG?");
var queryVector = new SqlVector<float>(query);

var topMatches = await ctx.Documents
    .OrderBy(d => EF.Functions.VectorDistance("cosine", d.Embedding, queryVector))
    .Take(5)
    .ToListAsync();
```

**⚡ Generated SQL:**
```sql
SELECT TOP(5) [d].[Id], [d].[Content], [d].[Embedding]
FROM [Documents] AS [d]
ORDER BY VECTOR_DISTANCE('cosine', [d].[Embedding], @queryVector)
```

`VECTOR_DISTANCE` supports common metrics: **`cosine`**, **`euclidean`**, **`dot`**. Cosine is
the typical pick for text embeddings.

## 💻 Cosmos DB vector search (EF 9/10)

For Cosmos, the API is similar but configured at the property + index level:

```csharp
modelBuilder.Entity<Document>(b => {
    b.Property(x => x.Embedding).IsVectorProperty(distanceFunction: DistanceFunction.Cosine, dimensions: 1536);
    b.HasIndex(x => x.Embedding).IsVectorIndex(type: VectorIndexType.QuantizedFlat);
});

var nearest = await ctx.Documents
    .OrderBy(d => EF.Functions.VectorDistance(d.Embedding, query))
    .Take(5)
    .ToListAsync();
```

(EF 10 renamed the model APIs to `IsVectorProperty` / `IsVectorIndex` — see
[What's New in EF Core 10](../08-Whats-New/01.EF-Core-10.md).)

## 🚫 PostgreSQL: `pgvector`

Npgsql doesn't ship vector support in core EF; the community **`Pgvector.EntityFrameworkCore`**
package gives you a similar pattern:

```csharp
public Vector Embedding { get; set; }   // from Pgvector
modelBuilder.Entity<Document>().HasIndex(d => d.Embedding).HasMethod("hnsw").HasOperators("vector_l2_ops");
```

Same shape; different package, different operators.

## ⚖️ Trade-offs

**Pros:** SQL-native math — the DB does the work, leveraging indexes and the optimizer; integrates
into normal EF queries (filter + order + project + paginate); pairs with **named query filters**
(EF 10) for multi-tenant RAG.
**Cons:** embeddings are large (1536 floats × 4 bytes = ~6 KB per row); high write volume needs
careful indexing; cross-version compatibility (the embedding model must match end to end).

## 🚫 Common mistakes

```csharp
// ❌ Mixing embedding models — query embeddings from a different model than what stored the data
// Distances are meaningless across models. Lock down the model version per dataset.

// ❌ No vector index → every query is a full scan
// SQL Server 2025 / Azure SQL: configure the appropriate vector index (depends on the column type
// and your provider; check the docs).

// ❌ Storing the vector in nvarchar — pre-EF-10 anti-pattern
// ✅ EF 10 `vector` column type with the correct dimensions
```

## 🆕 Latest EF Notes (8 / 9 / 10)

- **EF 8 / 9:** no first-class `vector` type for SQL Server. Cosmos got first-class vector model
  APIs in EF 9.
- **EF 10:** SQL Server 2025 / Azure SQL **`vector` type** + **`EF.Functions.VectorDistance`** with
  `cosine` / `euclidean` / `dot`; Cosmos vector model APIs renamed to **`IsVectorProperty`** /
  **`IsVectorIndex`**; also EF 10 added **Cosmos full-text search** (`EnableFullTextSearch`,
  `EF.Functions.FullTextContains`).

## 🌍 Real-world production tips

- **Persist the embedding model version** alongside the row (e.g. `EmbeddingModelId`). When you
  upgrade the model, you re-embed and partition queries.
- **Cap the number of returned nearest neighbors (Top-K)** — typically 5–50. Returning too many
  defeats the index.
- **Combine vector search with filters** (`Where(d => d.TenantId == ...)`) — works naturally with
  named query filters and your tenant scoping.
- For RAG: pair the **vector search** for retrieval with a **text-based reranker** for precision.

## 🎯 Practice (with full solutions)

### 1. Implement semantic search — `Medium`
**Task:** Given a question, return the top 5 most semantically similar documents.
**Solution:**
```csharp
public async Task<List<Document>> SearchAsync(string question, BloggingContext ctx, IEmbeddingModel model) {
    var q = new SqlVector<float>(await model.EmbedAsync(question));
    return await ctx.Documents
        .OrderBy(d => EF.Functions.VectorDistance("cosine", d.Embedding, q))
        .Take(5)
        .ToListAsync();
}
```
**Why it's better:** one SQL round-trip; vector index does the work; pagination/filters all
compose with the rest of EF.

### 2. Multi-tenant RAG — `Medium`
**Task:** Vector search must only return documents belonging to the current tenant.
**Solution (EF 10 named filter + vector):**
```csharp
modelBuilder.Entity<Document>()
    .HasQueryFilter("Tenant", d => d.TenantId == _tenant.Current);
// usage stays the same — query filter is auto-applied
var top = await ctx.Documents
    .OrderBy(d => EF.Functions.VectorDistance("cosine", d.Embedding, q))
    .Take(5).ToListAsync();
```
**Why it's better:** tenant scope is enforced automatically alongside vector search — no risk of
leaking embeddings across tenants from a forgotten `Where`.

## ✅ Key Takeaways

- EF 10 gives **first-class vector data** on SQL Server 2025 / Azure SQL: `vector(N)` column type
  + `EF.Functions.VectorDistance`.
- Use **`cosine`** for text embeddings; **`euclidean`** / **`dot`** for other shapes.
- **Cosmos DB** vector model uses `IsVectorProperty` / `IsVectorIndex` (renamed in EF 10).
- **PostgreSQL** users: `Pgvector.EntityFrameworkCore` is the community path.
- **Persist the model version**, **cap Top-K**, and combine with **named filters** for tenant
  isolation.
